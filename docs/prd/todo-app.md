# PRD — 개인용 일일 ToDo 앱

- **상태**: MVP(Phase 0~7) + 우선순위 드래그 재정렬 + 반복 루틴 자동 채움 전부 구현 완료. 마무리(RFC-0003, 다크 모드 등)만 진행 예정
- **최초 작성**: 2026-09-10
- **최근 갱신**: 2026-09-11 — 반복 루틴 자동 채움(§4.6) 구현 완료로 갱신
- **관련 RFC**: [`docs/rfcs/0001-mvp-phase-0-7.md`](../rfcs/0001-mvp-phase-0-7.md), [`docs/rfcs/0002-routine-auto-materialization.md`](../rfcs/0002-routine-auto-materialization.md), [`docs/rfcs/0004-priority-drag-reorder.md`](../rfcs/0004-priority-drag-reorder.md)

---

## 1. 왜 만드는가 (Why)

시중 ToDo 앱은 대부분 프로젝트 관리 기능이 많아 무겁다. 필요한 건
"**오늘 날짜에 무엇을 할지**"를 빠르게 적고 체크하는 것, 그리고 매일/매주
반복되는 일(물 마시기, 운동 등)을 매번 다시 입력하지 않는 것이다.

개인용이고, 한 사람이 자기 계정으로만 쓴다. 팀 공유·협업·알림은 범위 밖이다.

## 2. 목표 (What)

사용자가 회원가입/로그인 후:

1. 날짜별로 그 날의 할 일을 등록하고 완료 체크한다.
2. 이전/다음/오늘 버튼으로 날짜를 이동하며, 날짜별 목록이 분리된다.
3. 카테고리(이름 + 색상)를 만들어 할 일에 지정하고, 목록에서 색으로 구분한다.
4. 매일 또는 매주(요일 지정) 반복 루틴을 등록하면, 해당 날짜를 열 때
   그 날의 할 일로 자동으로 채워진다.

## 3. 사용자 & 시나리오

- **사용자**: 앱 소유자 본인 (단일 사용자 전제, 다만 계정 시스템은 다중 사용자 지원)
- **핵심 시나리오**:
  - 아침에 앱을 열면 오늘 날짜 페이지로 이동 → 어제 할 일과 섞이지 않은 오늘 목록을 본다.
  - 할 일을 한 줄 입력하고 Enter → 즉시 목록에 추가.
  - "운동" 카테고리(빨강)를 만들고 관련 할 일에 지정 → 목록에서 빨간 점으로 식별.
  - "물 마시기"를 매일 루틴으로 등록 → 내일, 모레 페이지에도 자동으로 나타남.
  - "회의 준비"를 매주 월·수 루틴으로 등록 → 월요일과 수요일에만 나타남.

## 4. 기능 요구사항

### 4.1 인증
- 아이디 + 비밀번호(Credentials)로만 가입/로그인. OAuth 없음.
- 아이디는 소문자로 정규화, 3~20자, 전역 유일. 비밀번호 8자 이상, bcrypt 해시 저장.
- 비로그인 상태로 보호 경로(`/day/*`, `/routines/*`) 접근 시 `/login`으로 리다이렉트.
- 모든 데이터는 소유자 격리: 다른 사용자의 항목은 조회·수정·삭제 불가.

### 4.2 일일 할 일
- 날짜별 목록 조회(`/day/YYYY-MM-DD`), 추가, 완료 토글, 삭제.
- 완료 여부는 항목마다 날짜별로 독립.
- 잘못된 날짜 형식은 오늘 날짜로 리다이렉트.
- 완료 항목도 목록에서 자리를 유지(취소선 처리).

### 4.3 날짜 이동
- 이전/다음 날짜 이동, "오늘로 가기" 링크(오늘이 아닐 때만 노출).
- 완료/전체 카운트 표시.

### 4.4 카테고리 + 색상
- 카테고리 = 이름 + 색상(`#rrggbb`, 컬러 피커로 선택). 별도 페이지(`/categories`)에서 CRUD.
- 할 일에 카테고리 지정/해제. 목록에서 색 점으로 표시, 점 클릭으로 인라인 변경.
- 카테고리 삭제 시 그 카테고리를 쓰던 할 일은 유지되고 분류만 해제된다(SetNull).

### 4.5 우선순위 순서 (드래그 재정렬)
- 날짜별 할 일 목록에서 항목을 드래그해 순서를 바꿀 수 있다.
- 바뀐 순서는 저장되어 새로고침 후에도 유지되고, 다른 날짜의 순서에는 영향을 주지 않는다.
- 새로 추가되는 항목(수동 추가·루틴 자동 생성 모두)은 그 날짜 목록의 맨 뒤에 붙는다.
- 상세 구현 계획: [`docs/rfcs/0004-priority-drag-reorder.md`](../rfcs/0004-priority-drag-reorder.md)

### 4.6 반복 루틴
- 루틴 = 제목 + 빈도(매일 / 매주+요일) + 활성 여부. `/routines`에서 CRUD.
- `startDate`는 서버가 생성 시점의 오늘로 설정(폼에 없음).
- **자동 채움**: 활성 루틴은 해당 날짜(`startDate` 이후, 오늘 이후)를 열 때
  그 날의 할 일로 지연 생성된다. 과거 날짜에는 소급 생성하지 않는다. (구현 완료 —
  [RFC-0002](../rfcs/0002-routine-auto-materialization.md))
- 비활성 루틴은 이후 날짜에 새 항목을 만들지 않지만, 이미 생성된 항목은 유지된다.
- 루틴 삭제 시 그 루틴에서 생성된 할 일은 유지되고 연결만 해제된다(SetNull).

## 5. 비범위 (Non-goals)

- 팀/공유 워크스페이스, 초대, 권한 관리
- 알림/푸시/이메일 리마인더
- 태그(카테고리와 별개), 마감 기한/기간, 하위 작업 (§8 참고 — 마감 기간은 향후 고려사항으로 검토 중이며 아직 확정된 범위는 아니다)
- 소셜 로그인(OAuth), 비밀번호 재설정 이메일 플로우
- 오프라인 지원, 모바일 네이티브 앱
- 월간/주간 캘린더 뷰 (현재는 하루 단위 페이지만)

## 6. 성공 기준

- 회원가입 → 자동 로그인 → 오늘 페이지까지 막힘 없이 도달.
- 할 일 추가/완료/삭제가 새로고침 후에도 유지되고, 날짜별로 분리된다.
- 카테고리 색상이 목록에 반영되고, 삭제 시 SetNull이 동작한다.
- 매일 루틴이 미래 날짜에 자동 생성되고, 완료 상태가 날짜별로 독립적이다.
- 매주 루틴이 지정 요일에만 나타난다.
- 두 번째 계정에서 첫 번째 계정 데이터가 전혀 보이지 않는다.

## 7. 제약

- 배포 대상은 Vercel + MongoDB Atlas.
- 패키지 매니저는 pnpm 고정.
- 컴포넌트 라이브러리 없이 순수 Tailwind CSS.

## 8. 향후 고려사항 (범위 미확정)

아직 RFC로 확정하지 않았지만, 다음에 검토할 때를 위해 논의된 방향을 기록해둔다.
아래는 **비범위(§5)를 뒤집는 결정이 아니라 검토 메모**이며, 실제로 만들기로 하면
PRD §5(비범위 조항 삭제)와 별도 RFC/ADR을 먼저 갱신한다.

- **마감 기간 + 캘린더 뷰**: 할 일에 `시작일~종료일` 형태의 마감 기간을 지정하고,
  월간 캘린더에서 확인할 수 있게 하는 아이디어. 논의된 표현 방식: 기간에 걸친
  막대(bar)가 아니라 **해당 기간의 각 날짜 칸에 카테고리 색 점/밑줄만 표시**하는
  가벼운 방식(겹치는 항목의 줄 쌓기 계산이 필요 없어 구현 비용이 낮다).
  결정 전에 풀어야 할 질문: 마감 기간이 있는 항목이 `/day/[date]` 목록에도
  기간 내 매일 나타나는지, 캘린더에만 나타나는지.
