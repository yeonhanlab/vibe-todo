# ADR-0007: 할 일 순서는 nullable 정수 필드 + 드롭 시 전체 재넘버링

## Status

Accepted (2026-09-11)

## Context

날짜별 할 일 목록에 드래그 재정렬을 추가한다 ([RFC-0004](../rfcs/0004-priority-drag-reorder.md)).
순서를 저장하는 방식에는 크게 두 갈래가 있다:

- **Fractional / gap-based 인덱스** (예: 순서 값에 실수 또는 큰 간격의 정수를 쓰고, 두 항목
  사이에 끼울 때 그 사이 값만 계산) — 대량의 항목이 실시간으로 동시에 재정렬되는 협업형
  리스트(칸반 보드 등)에 적합하지만, 정밀도 소진 시 주기적 재정규화가 필요해 구현이 더 복잡하다.
- **정수 전체 재넘버링** — 드롭이 끝날 때마다 그 날짜 목록 전체를 0..N-1로 다시 번호 매겨
  한 번에 쓴다.

이 앱은 개인용이고 하루치 목록 크기가 작다(수 개 ~ 수십 개). 동시 재정렬 충돌 가능성도
낮다(동시 접속자가 사실상 본인 1명). 또한 기존 `Todo` 문서에는 순서 필드가 없으므로,
필드를 새로 추가할 때 기존 데이터를 무중단으로 다루는 방법도 정해야 한다.

## Decision

- `Todo.order`를 **nullable `Int?`**로 추가한다(마이그레이션 없이 `pnpm run db:push`로 반영 가능,
  기존 문서는 필드 자체가 없는 상태로 남아도 됨).
- 정렬 기준은 `order asc`(있는 경우) → 동률/`null`은 `createdAt asc`로 폴백한다.
- 사용자가 그 날짜 목록에서 **처음 드래그를 완료하는 시점**에, 그 날짜의 현재 정렬 순서
  전체를 `order = 0, 1, 2, …`로 백필하며 한 번에 저장한다. 이후 재정렬도 같은 방식으로
  드롭할 때마다 그 날짜 목록 전체를 재넘버링한다.
- 새 항목(수동 추가, 루틴 자동 생성)은 그 날짜의 현재 최대 `order` + 1로 생성해 맨 뒤에 붙인다.
  `order`가 하나도 없는 날짜(아직 아무도 안 건드림)면 `null`로 두고 `createdAt` 정렬을 그대로 쓴다.
- Fractional/gap 인덱스는 도입하지 않는다.

## Consequences

- **장점**: 스키마 마이그레이션 스크립트가 필요 없다(레거시 문서는 `order` 없이도 정상 정렬).
  재정렬 로직이 "현재 화면 순서를 그대로 저장"이라 구현·디버깅이 단순하다(오버 엔지니어링 방지).
- **단점**: 항목이 많아지면(수백 개 이상) 드롭마다 전체를 다시 쓰는 비용이 커질 수 있다 —
  현재 사용 규모(개인용 일일 목록)에서는 문제되지 않는다고 판단. 규모가 커지면 gap 기반으로
  전환을 검토하고 새 ADR을 남긴다.
- 동시에 두 탭에서 같은 날짜를 재정렬하면 나중에 저장한 쪽이 이긴다(last-write-wins).
  개인용 단일 사용자 전제라 낙관적 잠금은 도입하지 않는다.
