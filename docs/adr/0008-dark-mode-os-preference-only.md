# ADR-0008: 다크 모드는 OS 설정만 따른다 (앱 내 토글 없음)

## Status

Accepted (2026-09-11)

## Context

라이트 배경(`bg-white`)에 명시적 텍스트 색을 지정하지 않은 입력창(로그인/회원가입)이
OS 다크 모드에서 브라우저 기본 폼 컨트롤 스타일 때문에 거의 안 보이는 회색 글자로
렌더링되는 문제가 보고됐다. 또한 헤더·버튼 등도 OS가 다크여도 항상 라이트로
고정되어 있었다(`docs/rfcs/0001` 기준 "body 배경 라이트 고정"이 원래 의도였음).

다크 모드를 지원하는 방법은 두 갈래다:

- **OS 설정만 따름** — Tailwind의 `dark:` variant(기본은 `prefers-color-scheme` 미디어
  쿼리 기반)를 그대로 쓴다. 별도 상태 저장, 토글 UI, 하이드레이션 처리가 필요 없다.
- **앱 내 토글** — 사용자가 라이트/다크를 직접 선택. `localStorage`(또는 서버 저장)에
  선택값을 유지하고, `<html data-theme="...">` 같은 클래스 전략으로 전환하며,
  SSR과 클라이언트 하이드레이션이 어긋나지 않게 초기 렌더 처리를 추가해야 한다.

## Decision

- OS 설정만 따르는 방식을 채택한다. Tailwind v4 기본 `dark:` variant(미디어 쿼리 기반)를
  그대로 사용하고, 토글 UI·저장 로직은 만들지 않는다.
- 색 토큰은 `app/globals.css`(폰트만 남김)가 아니라 각 컴포넌트에 `dark:` 클래스를
  직접 부여하는 방식으로 적용한다(기존 코드가 애초에 색을 컴포넌트별 Tailwind 클래스로
  관리하고 있어 이 패턴이 일관적).
- 입력창처럼 브라우저 기본 렌더링에 기댔던 요소는 라이트/다크 모두 **명시적** 텍스트·배경
  색을 지정한다(예: `text-zinc-900 dark:text-white`) — 이게 애초 버그의 근본 원인이었다.

## Consequences

- **장점**: 상태 관리·하이드레이션 이슈가 없다. 구현이 컴포넌트별 클래스 추가로 끝나서
  이 앱 규모(개인용, 페이지 5~6개)에 맞게 단순하다.
- **단점**: 사용자가 OS는 라이트인데 앱만 다크로(또는 그 반대로) 쓰고 싶어도 방법이 없다.
  필요해지면 `localStorage` + `<html data-theme>` 전략으로 전환하고, 그때 이 ADR의
  Status를 `Superseded by ADR-00XX`로 바꾼다.
- 새 컴포넌트를 추가할 때마다 라이트 클래스 옆에 `dark:` 클래스를 같이 챙겨야 한다
  (자동으로 보장되지 않음 — 리뷰 시 확인 필요).
